# GD-002 Compliance Verification: Stage Failure Visibility

## Golden Case

```yaml
id: GD-002
title: Stage Failure Visibility
intent: When any pipeline stage fails, the system must record the exact failure boundary.
expected:
  final_status: failed
  failed_stage: planner (exact stage name)
  stages_must_not_run_after_failure: [stylist, visualizer, critic]
anti_patterns:
  - failed_stage field is empty or generic
  - pipeline advances after failure
```

## Verification

### 1. `failed_stage` Setting

**Status: COMPLIANT**

The `failed_stage` field is correctly set in multiple locations:

**File**: `internal/application/orchestrator/session.go` (lines 96-104)

```go
func (s *sessionTracker) failStage(state domainagent.AgentState, status domainagent.RunStatus, errDetail *domainagent.ErrorDetail) {
    s.state.CurrentStage = state.Stage
    s.state.FailedStage = state.Stage  // <-- Exact stage name recorded
    s.state.Status = status
    s.state.Error = cloneErrorDetail(errDetail)
    s.state.UpdatedAt = state.Timing.CompletedAt
    s.state.CompletedAt = state.Timing.CompletedAt
    s.state.StageStates = append(s.state.StageStates, cloneAgentState(state))
}
```

Additionally, `RunResult.FailedStage` is set in `runner.go` (lines 237-240, 251-254):

```go
return RunResult{
    Session:     tracker.snapshot(),
    FailedStage: stage,  // <-- Also returned in RunResult
}, err
```

### 2. Downstream Stage Blocking

**Status: COMPLIANT**

When a stage fails, the `execute` method immediately returns via `finishStageError`. The for-loop in `execute` (runner.go lines 139-190) does NOT continue to the next iteration when an error occurs.

**Error handling flow in `execute` method**:

```go
for _, stage := range stages {
    // ... stage setup ...

    if err := stageAgent.Initialize(ctx); err != nil {
        return r.finishStageError(...)  // <-- Returns immediately, no continue
    }

    output, err := stageAgent.Execute(ctx, stageInput)
    if err != nil {
        // ... cleanup ...
        return r.finishStageError(...)  // <-- Returns immediately, no continue
    }

    if err := stageAgent.Cleanup(ctx); err != nil {
        return r.finishStageError(...)  // <-- Returns immediately, no continue
    }
    // ... success path ...
}
```

All error paths use `return`, not `continue`. This ensures that when `planner` fails, the downstream stages (`stylist`, `visualizer`, `critic`) are never executed.

### 3. `final_status` Setting

**Status: COMPLIANT**

The final status is set to `failed` in `sessionTracker.failStage`:

```go
s.state.Status = status  // status = domainagent.StatusFailed
```

And the `StatusFailed` constant is defined in `internal/domain/agent/types.go` (line 38):

```go
StatusFailed RunStatus = "failed"
```

## Anti-Pattern Check

| Anti-Pattern | Status |
|--------------|--------|
| `failed_stage` field is empty or generic | **NOT PRESENT** - Exact stage name is recorded |
| Pipeline advances after failure | **NOT PRESENT** - Execute returns immediately on error |

## Conclusion

**GD-002 is FULLY COMPLIANT.**

All three verification criteria are satisfied:
- [x] `failed_stage` is correctly set to the exact stage name (e.g., `planner`)
- [x] Downstream stages are blocked from executing after a failure
- [x] `final_status` is set to `failed`

The error handling architecture uses immediate return semantics with a dedicated `finishStageError` helper that:
1. Records the exact failure stage in both `SessionState.FailedStage` and `RunResult.FailedStage`
2. Sets the session status to `StatusFailed`
3. Emits appropriate failure events (`EventStageFailed`, `EventRunFailed`)
4. Persists the failure state via snapshot (if configured)

No fixes are required.
