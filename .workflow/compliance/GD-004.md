# GD-004: Retrieval Constrains Planning

## Golden Case

```yaml
id: GD-004
title: Retrieval Constrains Planning
intent: Retrieved references must have observable causal influence on planner input.
expected:
  retriever_must_produce_bundle: true
  planner_must_receive_bundle: true
  plan_must_reflect_references: true
anti_patterns:
  - retriever runs but planner receives empty references
  - planner output identical regardless of retrieval
```

**Overall Status: COMPLIANT**

The system correctly implements the data flow from retriever to planner:
1. Retriever outputs both `RetrievedReferences` and `GeneratedArtifacts` (reference bundle)
2. Orchestrator's `mergeAgentInput` propagates these artifacts to the next stage
3. Planner explicitly decodes the bundle and uses examples to construct the prompt
4. The artifact chain is preserved through the pipeline stages

No anti-patterns detected:
- References are never dropped between stages
- Planner output depends on retrieved examples (observable in metadata and LLM request)
